# 系统功能说明

> 版本：2026-10-29 ｜ 适用仓库：`ABC-GIT-128/course-bank` ｜ 线上：https://abc-git-128.github.io/course-bank/

## 0. 一句话定位

**纯静态题库站**：零服务器、零数据库、零登录。内容以 Git 仓库里的 JS 文件为唯一数据源，
投稿走 GitHub Issue 表单，审核通过后由 Actions 自动生成 PR，合并即上线。

---

## 1. 总体架构

| 层 | 实现 | 说明 |
|---|---|---|
| 前端 | 纯 HTML/CSS/JS + PWA | 无框架、无打包，双击可跑 |
| 数据 | `data/*.js`（`window.OC = {course, questions}`） | 一门课一个文件，Git 兼容性好 |
| 索引 | `data/courses.js` | **构建产物**，部署时现生成，不入库 |
| 状态 | `data/_status.js` | 唯一下架/归档来源，运行时也读它 |
| 构建 | `scripts/build-index.js`、`check-data.js` | 生成索引与短地址；校验 + 隐私扫描 |
| 门槛 | Actions `pages.yml` | 校验不过就不发布 |
| 投稿 | Actions `question-pr.yml` | Issue → 解析 → 写数据 → 开 PR |
| 存储 | GitHub 仓库 | 相当于数据库 + 版本历史 + 审计 |

## 3. 学生端板块

### 3.1 首页

- **作用**：让来访者 3 秒内找到自己那门课。
- **流程**：搜索框输入（`/` 聚焦、`Esc` 清空）→ 结果实时过滤（课程名/章节/关键词/标签/学期）→ 点卡片进刷题页。
- **卡片信息**：课程名、副标题、题量、章节数、更新日期、题型分布、`重点`/`PPT 专节` 数量、学期标签、归档角标。
- **页脚**：许可说明 + **数据更新时间**（用于判断自己看到的是不是最新）。

### 3.2 刷题页

- **入口**：`/<课程id>/`（如 `/sensor/`）或兼容老链接 `quiz.html?course=sensor`。
- **流程**：进入即渲染全部题目 → 逐题作答 → 即时判分 → 自动展开解析 → 进度与错题累计。
- **题型与判定**：
  - 选择：点选项即判，选中项红/绿 + 对错标记
  - 填空：逐空判定，支持同义答案（`/` 分隔）
  - 名词解释：按**要点命中率**判定（命中 3/5 即算正确）
  - 计算：数值 + 容差（默认 3%），带单位
- **筛选**：全部 / 重点 / PPT 专节 / 选择 / 填空 / 名词解释 / 计算 / 错题本
- **工具**：随机顺序（记忆）、跳到下一道未答、重置、键盘 `1~4` 选项、`←→` 翻题。
- **进度**：按课程存 `localStorage`，不联网、不上传。

### 3.3 批量整理页

- **作用**：把「整段题目」变成「可入库的题目」，并且**在提交前就暴露格式错误**。
- **流程**：粘贴 → 实时解析 → 统计条（识别 N 题 / 各题型 / 跳过数）→ 红色报错清单 → 修正 → 「去投稿」。
- **附加**：填入示例、清空、复制原文、**复制 AI 整理指令**、看格式要求（滚动定位 + 高亮）。
- **「去投稿」行为**：先校验；有错则拦截并滚回顶部；无错则**复制全文到剪贴板**并打开 GitHub 表单（省一次手动复制）。

### 3.4 关于页

- 内容来源分层（自编题 / 改写题 / 已授权材料 / 公版教材）
- 许可（代码 MIT、内容 CC BY-NC-SA 4.0）
- 保留年限（近两学年，超出归档）
- 下架承诺（72 小时）与通道
- 投稿两种形态（单题 / 整份文档）与 AI 指令入口
- 隐私说明（无 Cookie、无统计、进度仅本地）

### 3.5 PWA

- 可「添加到主屏幕」，独立窗口、断网可打开
- 缓存策略：页面导航网络优先；`data/*.js` 网络优先；其它资源缓存优先 + 后台更新
- 每次部署给资源加 `?v=时间戳`，穿透旧缓存

## 4. 管理端板块

### 4.1 Issue 表单（三套）

| 模板 | 标签 | 字段数 | 用途 |
|---|---|---|---|
| 批量提交题目（一次多题） | `contribution` `batch` `question` | 4 + 版权确认 | 一次多题、四型混排（推荐） |
| 新增题目 | `contribution` `question` | 11 + 版权确认 | 单题，一栏一字段 |
| 新增课程 | `contribution` `course` | 5 | 只提需求，不含原文 |

### 4.2 审核与合并（管理员核心动作）

1. Issues 列表 → 打开投稿 → 核对四条（答案 / 解析 / 出处 / 版权）
2. 通过：加 `approved` 标签 → 机器人解析入库并开 PR
3. 打开 PR → 看描述里的解析摘要与 diff → `Merge pull request`
4. 驳回：不加标签，评论说明后关闭

### 4.3 状态表 `_status.js`

三种状态，改一个文件即可（部署时重建索引）：

| status | 首页 | 课程页 | 数据 |
|---|---|---|---|
| `active`（默认） | 正常 | 正常 | 在 |
| `archived` | 折叠「往期课程」+ 灰角标 | 黄条提示"可能过期" | 在 |
| `hidden` | 不显示 | 「本课程已下架（原因）」 | 在，可恢复 |

### 4.4 命令行脚本

| 命令 | 作用 |
|---|---|
| `npm run build` | 生成索引与课程短地址 |
| `npm run verify` | 构建 + 校验（含隐私扫描） |
| `npm run new-course -- --id … --title …` | 新建课程骨架 |
| `npm run import -- --file x.csv --course …` | CSV 批量导入 |
| `npm run admin -- list / hide / show / hide-course / show-course / archive / retire / log` | 下架、恢复、归档、记录 |
| `npm run admin -- purge <课程id> --yes` | 物理删除整门课 |
| `npm run admin -- purge-q <题目id> --course <课程id> --yes` | 物理删除单题 |
| `npm run parse -- --body-file …` / `parse-batch` | 本地复现投稿解析 |

**物理删除的限制**：Git 历史仍保留；fork 副本与 CDN 缓存不可撤回；涉及个人信息需 `git filter-repo` 重写历史。

### 4.5 Actions

| 工作流 | 触发 | 动作 |
|---|---|---|
| `question-pr.yml` | Issue 打开 / 打标签 | triage 自动补标签、回帖；`approved` 后解析→入库→校验→开 PR→回帖 |
| `pages.yml` | push main | 构建索引 → 校验 → 打包 → 加版本号 → 部署 |

## 5. 上传功能规格（重点）

### 5.1 三条通道，都不收文件

| 通道 | 形式 | 适合 |
|---|---|---|
| A 批量粘贴 | GitHub Issue 表单（文本域） | 5~50 题，四型混排 |
| B 单题表单 | GitHub Issue 表单（分字段） | 1~2 题 |
| C 整份文档 | **线下**：发维护者 → 整理成题目 → 本地导入 | 课件、复习要点、往年卷 |

### 5.2 文件上传：不支持（明确说明）

| 项目 | 现状 |
|---|---|
| 支持的文件类型 | **无**（不接受 docx/pdf/pptx/图片等任何文件） |
| 文件大小限制 | 不适用 |
| 文件存储位置 | 不存储。原始文档只留在维护者本地 `raw/`（已被 `.gitignore` 忽略，永不入库） |
| 为什么 | 纯静态站没有接收接口；公开仓库的提交历史不可撤销；课件常含教师姓名/学生信息/教材插图 |
| 替代路径 | 先让 AI 按指令转成题目文本，再走通道 A/B。**指令分两份**，按资料性质选（见 5.2.1） |

#### 5.2.1 两份 AI 指令的区别（重要）

| 指令 | 适用前提 | AI 会做什么 | 不会做什么 |
|---|---|---|---|
| `templates/ai-prompt.txt` | 资料**还不是题目**（复习要点、课件文字） | 把知识点改写成题目、自己写解析 | — |
| `templates/ai-prompt-normalize.txt` | 资料**本身就是题目**（往年卷、练习题、带答案题库） | 只做格式规整：加题型标记、统一选项符号、空位统一为 `＿＿＿`、补 `答案/解析/出处` 行 | **不改写题干、不增删题、不改答案、不编解析**；缺答案写「答案：待补」，缺解析写「解析：原文未提供解析，待补充。」 |

批量整理页底部可切换这两种模式，各自一键复制。选错模式的后果：用「生成」指令处理现成题目，AI 会重写题干甚至编答案。

> 唯一的"大小"约束来自平台：GitHub Issue 正文上限 **65,536 字符**（约 30~60 道题的文本量）。

### 5.3 批量表单字段（`.github/ISSUE_TEMPLATE/batch.yml`）

| 字段 | 类型 | 必填 | 默认值 | 说明 / 校验 |
|---|---|---|---|---|
| 所属课程 | dropdown | ✅ | 无 | 选项目前写死两项：`传感器与检测技术（sensor）`、`其它（请在下一项填写课程 ID）` |
| 课程 ID | input | ⭕ 选「其它」时必填 | 空 | 只能英文/数字/`-`/`_`；对应 `data/<id>.js` 文件名 |
| 默认章节 | input | ❌ | 无 | 题目未写「出处：第X章」时使用；不填则按 `1` |
| 题目内容 | textarea | ✅ | 无 | 整段文本，格式见 5.5 |
| 版权确认 | checkboxes（2 项） | ✅ 全勾 | 未勾 | 两项均为 `required`，未勾无法提交 |

表单固定打上三个标签：`contribution`、`batch`、`question`。

### 5.4 单题表单字段（`new-question.yml`）

| 字段 | 必填 | 默认 / 校验 |
|---|---|---|
| 所属课程 | ✅ | 同上两项 |
| 课程 ID | ⭕ | 选「其它」时必填 |
| 章节 | ✅ | 取第一个数字，如「第 5 章」→ `5` |
| 题型 | ✅ | 四选一：单项选择 / 填空题 / 名词解释 / 计算题 |
| 题干 | ✅ | 填空须写 `＿＿＿`（三个全角下划线） |
| 选项（选择题填） | ❌ | 每行一个，`A.` 开头；选择题至少 2 个 |
| 答案 | ✅ | 选择写字母；填空按空顺序用 `|` 分隔；计算以数值开头 |
| 关键词 / 要点 | ❌ | 名词解释用，至少 3 组，`|` 分隔 |
| 单位与容差 | ❌ | 计算题用，如 `V 0.02`；不填默认容差 3% |
| 解析 | ✅ | 少于 8 个字符视为不合格 |
| 出处 | ✅ | 文本框（批量通道里可缺，缺了只警告） |
| 版权确认 | ✅ 全勾 | 同批量 |

### 5.5 文本格式规则（批量通道）

- 题型标记：`【选择】/【填空】/【名词】/【计算】`，也认 `[选择]`、`## 选择`、`一、选择题`；可独占一行，也可与题干同行
- 字段锚点：`答案：`、`解析：`、`出处：`、`关键词：`、`单位：`、`章节：`（全角/半角冒号均可）
- 同一题型可连写多题：以 `3.` 这类题号起新行，且上一题已有答案行
- 章节号：优先 `章节：`，否则从「出处：第 4 章」推断，都没有则用「默认章节」或 `1`
- 干扰项会**截断**：末尾的 `【未生成】…`（AI 提示词的收尾格式）会被识别并丢弃，不会污染最后一题的出处

### 5.6 校验规则

| 级别 | 规则 | 结果 |
|---|---|---|
| 阻断 | 选择题选项 < 2 个 | 该题跳过 |
| 阻断 | 答案无法识别（非 A~D 且非序号）或越界 | 该题跳过 |
| 阻断 | 填空题空位数 ≠ 答案组数 | 该题跳过 |
| 阻断 | 名词解释关键词 < 3 组 | 该题跳过 |
| 阻断 | 计算题答案非数值 / 无解题步骤 | 该题跳过 |
| 阻断 | 题干为空、解析 < 8 字符 | 该题跳过 |
| 跳过 + 明确提示 | 答案写「待补 / 待定 / 未知 / ?」 | 跳过该题，提示「需要先补上正确答案」 |
| 仅警告 | 缺「出处」 | 仍入库，页面标"待补" |
| 部署阻断 | `check-data.js`：id 重复、type 非法、缺 ch、选项不足、ans 越界、空位数不符 | **整次部署失败**，不发布 |
| 部署阻断 | 隐私扫描命中：手机号、身份证号、疑似学号、`成绩单/花名册/学生名单/答题卡` | 整次部署失败 |

**部分成功策略**：一批里有的题不合格，只会跳过那几题，其余照常入库并在 Issue 回帖逐条说明原因。

### 5.7 数量与权限限制

| 维度 | 限制 |
|---|---|
| 单次题量 | **代码里没有硬上限**；受 Issue 正文 65,536 字符约束；AI 提示词里建议 ≤50 题（软约束） |
| 单文件 | 无（不接收文件） |
| 提交权限 | 任何 GitHub 账号均可建 Issue；无需账号可线下交给维护者代录 |
| 放行权限 | 加 `approved` / 合并 PR 需**仓库写权限**（只有维护者） |
| 重复处理 | 按「课程 id + 题目 id」判重；**不做内容级查重**（同一批题提交两次会重复入库） |
| 频率 | 无限制 |
| 站点侧 | 全程只读，访客无任何写权限，无登录体系 |

## 6. 内容治理

- **保留窗口**：近 2 个学年（如 2026 年保留 2025、2026），超出自动 `archived`
- **归档不删**：折叠进「往期课程」，可搜索可查看，页内提示可能过期
- **下架可恢复**：`hidden` 只改状态，数据仍在
- **物理删除**：`purge` / `purge-q`，删文件 + 删短地址目录；Git 历史仍可追溯
- **授权留痕**：`consent/` 目录记授权情况（仅提交说明，具体凭证不入库）

## 6.1 安全与发布（2026-10-30 加固）

| 项 | 做法 |
|---|---|
| 内容渲染 | 所有题库字段经 `esc()` 全转义后，只放行 `<p> <br> <b> <i> <sub> <sup>` 六个无属性标签（`rich()`）。`<img onerror=…>` 会原样显示成文本 |
| 发布裁剪 | 新增 `scripts/prune-build.js`：下架课程的 `data/<id>.js` **不进产物**，短地址页替换为不含数据的静态提示页；单题下架的题从课程文件中剔除；索引中移除下架课程 |
| 课程 ID 校验 | `add-question.js` / `parse-batch.js` 统一白名单 `^[a-z0-9][a-z0-9_-]{0,63}$`，并校验解析后的路径仍在 `data/` 内 |
| 投稿口径 | 预览页与 CI 统一为「部分成功」：有错题时可确认后提交，只入库合格部分 |
| 文案自查 | 移除关于页"可导出进度"的不实承诺 |
| 版权校验 | 批量解析会检查「版权确认」两项是否都勾选；勾不全直接拒绝入库。手工建的 Issue 没有该小节时只告警，由维护者人工确认 |
| 合并即关单 | 自动生成的 PR 描述含 `Closes #N`，合并后 Issue 自动关闭；`merge-note.yml` 再回帖「已上线 + 数据版本号」并兜底关单 |
| 版本可追溯 | 每次部署把 `commit / ref / 时间` 写入 `data/build-info.json`，首页页脚显示「题库数据更新于 … · 版本 abc1234」 |
| 供应链 | 所有 Actions 固定到具体提交 SHA（不再用 `@v4` 这类浮动标签） |
| 分支保护 | `main` 禁止强制推送与删除分支（未强制 PR 审核，保留单人维护的直接推送能力） |

> 仍存在的边界：Git 历史、已 fork 的副本、CDN 与浏览器缓存无法撤回；
> 涉及个人信息的彻底删除仍需 `git filter-repo` 重写历史。

## 7. 已知限制与未实现

| 项 | 现状 |
|---|---|
| 账号 / 跨设备进度同步 | 未实现（进度仅本地） |
| 网页端上传文件 + 审核后台 | 未实现（需后端，约 3~5 天） |
| 排行榜 / 统计 | 未实现（无后端、不采集） |
| 试卷模式（计时、交卷、评分） | 未实现 |
| 图片题 / 公式渲染（LaTeX） | 未实现；公式用普通字符 |
| 内容级查重 | 未实现，重复投稿会重复入库 |
| `_status.js` 语法错 | 部署裁剪阶段会直接失败（prune-build 解析不出状态就中止），避免把下架内容发出去；但本地构建仍只告警 |
| 表单课程下拉 | 写死两项，新增课程需手动加到 `batch.yml` / `new-question.yml` |
| 移动端管理 | 只能做"审投稿、合并 PR"，改状态需网页编辑文件 |
